# Exercises

## Day 1 Exercises

### Exercise 1 - Project reality (20 minutes)

**Goal:** recognize a project and judge success.

**Process**

1. Form a group of 4-5 students.
2. Choose one example:
   * a project reported in a local or national news source;
   * a project at the university or in a student organization;
   * a known software or IT project.
3. Assign the following roles:
   * **Source Finder:** locate at least one reliable primary or original source and one secondary source if available. Record title, date, URL, and key facts. Separate verified evidence from opinions or later claims.
   * **Goal and Stakeholder Reviewer:** restate the project's original goal from evidence. Identify the sponsor, customer, users, and other relevant stakeholders. State who would judge whether the goal was achieved.
   * **Constraint Reviewer:** identify scope/quality expectations, deadline, budget or resources, dependencies, and unique project conditions. Record at least one known constraint and one known risk.
   * **Success Reviewer:** compare the available evidence against scope/quality, time, budget/resources, and value. Mark each dimension as achieved, not achieved, or unknown. Challenge unsupported success claims.
   * **With five members:** assign one person as facilitator and quality checker. This person tracks time, ensures that every role has evidence, coordinates the presentation, and checks for unsupported assertions.
4. Search for evidence for at least two of the success dimensions. Do not use unsupported assumptions.
5. For each uncertain fact, write "uncertain" and state what evidence would be required.
6. Prepare a maximum three-minute presentation.

**Presentation structure**

1. Project and original goal - 30 seconds
2. Constraints and stakeholders - 30 seconds
3. Success result - 60 seconds
4. Unresolved question or ambiguity - 60 seconds

**Deliverable**

Submit one project profile as a short table:

| Item             | Result                            |
| ---------------- | --------------------------------- |
| Source           |                                   |
| Project goal     |                                   |
| Constraints      |                                   |
| Stakeholders     |                                   |
| Scope/quality    | achieved / not achieved / unknown |
| Time             | achieved / not achieved / unknown |
| Budget/resources | achieved / not achieved / unknown |
| Value            | achieved / not achieved / unknown |
| Ambiguity        |                                   |
| Justification    |                                   |

### Exercise 2 - SMART goals and the magic triangle (45 minutes)

**Goal:** formulate measurable goals and plan trade-offs.

Given: "Develop a campus study-room booking application."

**Process**

1. Keep the same application context for the full exercise.
2. Individually write one proposal for 3 minutes:
   * one outcome goal;
   * one process goal;
   * one non-goal.
3. Compare proposals in the group. Choose or combine the strongest outcome goal.
4. Check the outcome goal against all five SMART criteria. Rewrite it until each criterion is explicit.
5. State a target for scope/quality, time, and budget. These values may be assumed, but they must be documented.
6. Change **one** dimension once. For example: add 20% more features, shorten delivery by four weeks, or reduce the budget by 15%.
7. Add one compensating measure for each other affected dimension. Explain the project-management consequence in one sentence.
8. Create a Gantt table with five phases. Each phase needs a start, end, dependency, responsible role, and result.
9. Mark at least two milestones as `MILESTONE`. A milestone must describe a result or decision, not an activity.
10. Use GanttProject for creating the project plan requested above [https://www.ganttproject.biz/](https://www.ganttproject.biz/)

**Deliverable**

1. Submit the following in one document:

```
Outcome goal:
Process goal:
Non-goal:
SMART rewrite:

Original scope/quality:
Original time:
Original budget:

Changed dimension and value:
Compensating measure 1:
Compensating measure 2:
Risk introduced:

```

2. Submitt the GanttProject file with your project plannt



**Quality check**

* No goal uses vague terms such as "good", "fast", or "user-friendly" without a measurable definition.
* A non-goal is not a hidden requirement.
* Every Gantt dependency is valid.
* Every milestone is a clear result or decision.

### Exercise 3 - Scrum map (45-60 minutes)

**Goal:** connect Scrum roles, events, and artifacts.

Use groups and a large paper board or Miro:

**Process**

1. Draw a vertical Sprint flow on the board.
2. Place these labels at least once:
   * Product Goal;
   * Product Backlog;
   * Sprint Goal;
   * Sprint Backlog;
   * Increment;
   * Definition of Done.
3. Place the following accountabilities beside their main decisions:
   * Product Owner;
   * Scrum Master;
   * Developers.
4. Place the five events in the correct order. For every event, add:
   * purpose;
   * maximum or fixed time-box, if defined;
   * main accountabilities involved.
5. Draw arrows for information and work flow:
   * backlog to Sprint planning;
   * planning to Sprint work;
   * work to review and increment;
   * review or retrospective to improvement.
6. Add one short example for an empirical cycle:
   * one observation;
   * one inspection;
   * one adaptation.
7. Exchange boards with another group.
8. Open the official [Scrum Guide](https://scrumguides.org/) and give the other group one correct and one incorrect finding. Both findings must cite a page or paragraph from the guide.

**Deliverable**

* one photographed or exported Scrum map;
* a 5-line role/artifact summary;
* one correction list with guide evidence;
* each group member's name next to the part they explained.

**Quality check**

* Do not use old or inaccurate terminology such as "Scrum team" as a separate accountability when the current guide is available.
* Do not invent a time-box for an event.
* The Product Goal belongs to the Product Backlog as its long-term objective.
* The Definition of Done belongs to the Increment commitment.

### Exercise 4 - Agile value ranking (30 minutes)

Choose one of these scenarios:

* a customer adds a major feature during a sprint;
* a detailed specification conflicts with better technical evidence;
* a team has a working prototype and incomplete documentation;
* a developer works silently instead of discussing a blocker.

**Process**

1. Copy the chosen scenario on the board.
2. Identify both applicable Agile Manifesto values:
   * the left-hand value;
   * the corresponding right-hand value.
3. Explain why one value receives priority in this situation.
4. Do not describe "ignore the right-hand value" as the result. Name one way the right-hand value can remain useful.
5. Define one concrete team action.
6. Add one escalation or traditional control rule that may be necessary.
7. Prepare a 90-second justification.

**Deliverable**

```
Scenario:
Left-hand value:
Right-hand value:
Priority reason:
How the right-hand value remains useful:
Proposed team action:
When a traditional control remains necessary:
```

**Quality check**

The team action must be observable, assigned to a role or meeting, and not involve blaming an individual.

### AI practice (15-20 minutes)

**Process**

1. Prompt an AI tool: `Draft a Scrum meeting agenda and Gantt risk checklist for a 4-person software team.`
2. Ask the tool to mark uncertain claims or assumptions.
3. Compare every Scrum detail with the official Scrum Guide.
4. Compare every Gantt risk with at least one project-management assumption.
5. Mark unsupported claims with `[UNSUPPORTED]`.
6. Correct at least three points in the output.
7. Add the original prompt, AI output, and human corrections to the deliverable.

**Deliverable**

Submit:

* the exact prompt;
* the AI output excerpt;
* a marked copy with at least three `[UNSUPPORTED]` or `[CORRECTED]` notes;
* a five-line human review;
* one remaining limitation or risk.
